# 回传主控

以下字段由专项对话填写后整段输出，供 Leo 复制。填写实际情况；“未运行”“未生成”“待 Leo 试玩”和“不适用”均是有效状态。不要把计划写成已完成事实。

```text
【回传主控】
项目名称 / 项目 ID：
专项名称 / 任务 ID：
基于 PROJECT 修订号 / 游戏版本：
本次状态：完成待验收 / 部分完成 / 受阻（选一并说明）

1. 本次实际完成
简要说明实际成果及采取的设计决定。

2. 交付文件
逐项列出文件路径或可访问链接、用途、格式/规格和资源版本。
标明哪些是正式成果，哪些只是占位、制作规格或待生成素材。
若只输出了文字，写“已输出文字，尚未保存文件”。

3. 验收与证据
实际检查或试玩了什么、环境与版本、结果和证据位置。
分开列出已通过、失败和未执行；不声称替代真实教师/学生试玩。

4. LOCKED 影响
逐项列出相关锁定 ID：保持一致 / 发现冲突 / 请求变更。
如需变更，说明理由、影响和需重测项；不要自行解锁。

5. 建议主控更新 PROJECT.md
用“字段或章节：原值 → 建议值”的形式列出变更；新增内容写“无 → 建议内容”。
区分已验证事实、设计建议和仍需 Leo 决定的内容。

6. 已知问题与未完成项
说明问题、影响范围、缺少的输入和可行的后续处理。

7. 后续专项的输入
列出可以交接的资源、接入约定、依赖顺序和建议下一步。
下一阶段由主控验收后决定。
【回传结束】
```
