# 专项首条消息生成规范

主控在派发时读取对应专项。下面是供主控组装的模板，不要让 Leo 自己组装。输出给 Leo 的首条消息必须是“共同任务头 + 当前专项完整任务内容 + 完整回传格式”的一个可复制文本块。不要省略为“见模板”，不要遗留花括号变量。

## 共同任务头

```text
你是 Leo 小学数学 HTML 小游戏项目的【实际专项名称】负责人。这是专项对话，主控对话负责总进度和 PROJECT.md 的更新。请只完成以下任务，并在结束时输出“回传主控”摘要。

项目名称与 ID：【实际值】
任务 ID：【实际值】
当前阶段 / 游戏版本：【实际值】
基于 PROJECT 修订号：【实际值】
项目目录 / 当前运行入口：【实际值；不存在则说明】

项目事实：
【嵌入年级、知识范围、数学行为目标、核心循环、计分/完成规则、设备与交付约束，以及本专项依赖的相关事实。】

LOCKED：
【逐项写出本任务相关的完整 ID 与内容；尚无时写明尚无。】

EXPLORING：
【写出本次可以探索的具体项。】

输入与文件：
【列出实际路径/链接、用途、版本；需要上传时说明。若无法访问，要求先指出缺失内容，不得假装读过。】

允许创建/修改：【当前专项具体目录、文件或纯文字交付范围。】
不要直接修改 PROJECT.md；在回传中列出建议，由主控合并。保持现有 LOCKED 项；必要变更先写明影响，已有明确授权则按任务书执行，没有授权则提交主控决定。

本次任务与验收：
【嵌入下面对应专项的内容，按实际项目具体化。】

工具与交付：
先检查当前可用工具；专业素材优先使用专业工具。缺工具时给出完整制作规格与可复制提示词，清楚标记待制作，不把提示词或占位图称为已完成素材。文件交付需列出实际路径、用途和规格，确保主控能获取成果。

完成后请输出以下“回传主控”摘要，供我整段复制回主控：
【在这里嵌入 assets/RETURN.template.md 中代码块内的全部字段。】
```

## 1. 教学与玩法

派发时机：新游戏已具备大致教学意图，尚未验证核心循环；或明确授权重做玩法。首句：“现在，你重新开一个对话，向他发送以下内容，开始你的教学与玩法设计：”

嵌入任务内容：

```text
请把教学目标转化为可试玩的核心循环，暂不投入正式角色、背景、动画和音乐制作。
1. 明确学生基础、知识与数值范围，以及希望观察到的数学行为。区分“答对”与“使用了什么策略”；不要把快速点击直接当作理解数学。
2. 设计“看到什么→做什么→系统反馈什么→下一步”。写清题目生成、判定、错误后的重试/解释、计分、进度与结束/重玩规则。
3. 如存在关键分歧，只给少量实质不同的方案和推荐理由；已有玩法时直接完善，不重新发散。
4. 给出一轮完整的学生操作示例，覆盖正确、错误和一个重要边界情况；检查游戏行为是否服务于数学目标。
5. 写出 v0.1 最小原型任务书：仅需文字、色块、必要点击和即时反馈；列出原型不需要的装饰资源。
6. 给出 Leo 试玩时要观察的问题，以及判断核心循环是否成立的证据。
交付：玩法设计、待定问题、建议 LOCKED/EXPLORING 项及 v0.1 原型验收条目。设计建议须等待实际试玩验证，不能自行宣布已经验证有效。
```

## 2. 游戏开发

派发时机：玩法设计足以制作原型，或某项资源已经被主控接受并准备接入，或已有明确缺陷待修。首句：“现在，你重新开一个对话，向他发送以下内容，开始你的游戏开发（【原型/接入/修复/收尾】）：”

主控只插入当前模式，不让开发同时执行四种模式。

### 原型模式 — v0.1

```text
依据当前玩法任务书制作可在目标浏览器运行的最低成本 HTML 原型。用文字、色块和简单反馈，把一轮游戏与重玩跑通。
保留清楚的题目状态、输入判定、反馈和进度；暂不制作正式角色、美术、复杂动画与音乐。检查题目边界、计分/完成规则和错误后重试，避免猜测未定规则。
交付可运行文件、启动方法、实现的循环、尚未实现项及简短教师试玩步骤。实际运行时记录浏览器和结果；未能运行时明确写未验证。
保留 v0.1 候选成果供 Leo 试玩；由主控收到实际试玩反馈后决定是否接受玩法，不自行进入正式美术生产。
```

### 接入模式 — v0.2 / v0.3 / v0.4

```text
仅接入本任务列出的已接受资源；保持数学目标、题目规则、计分和相关 LOCKED 项一致。不要顺手重构其他玩法。
读取资源清单与规格，明确事件→游戏状态→视觉/音频反馈的映射；处理重复点击、动作中断、重启清理及资源加载失败。声音遵循浏览器首次交互播放要求，并提供静音控制。
完成后运行与本次接入相关的检查：资源加载、当前功能、重玩，以及核心数学规则的针对性回归。报告实际测试证据，不宣称自动测试等价于学生试玩。
交付可运行版本、变更文件、接入说明、问题及恢复点。快照包含全部依赖资源，不能只保存 HTML。
```

### 修复模式

```text
先复现任务书中的问题，说明触发步骤、预期和实际表现；仅修复相关范围。涉及 LOCKED 项时先指出冲突，不以修 bug 为由改变玩法。
交付修复文件、修复前后现象、针对性复测与相关规则回归结果，以及仍未解决的问题。若无法复现，说明环境差异和需要的证据，避免猜测性大改。
```

### 收尾模式 — v1.0 候选

```text
按主控验收清单整理当前 HTML 游戏与依赖资源，检查路径和启动方式，保留已知限制与版本恢复点。根据实际约束交付静态目录或单 HTML，以及供 Leo 使用的简短说明。
核对教师和真实学生试玩证据；缺少时明确标记候选版/待试玩，不自行宣称 v1.0 验收通过。发布到外部平台只有在任务书明确要求时才执行。
列出值得复用的组件及其文件位置，先记 Kit 候选，不在收尾时额外改造成大框架。
```

## 3. 美术与角色

派发时机：v0.1 核心循环已经试玩通过，或已有正式角色需要新增状态；不可凭“原型代码完成”跳过玩法试玩。首句：“现在，你重新开一个对话，向他发送以下内容，开始你的美术与角色设计：”

```text
先形成完整角色设定与全局视觉规范，再拆解生产素材。若角色主视觉已经 LOCKED，严格沿用，不重新设计。
先交付可评审的角色主设定：轮廓、比例、配色、性格、关键识别特征，以及项目实际需要的正面/侧面或动作参考。给出背景、按钮、文字和数学对象的视觉关系；优先保证数值、数量与操作目标可辨认，避免装饰干扰计数。
角色设定未获确认时先停在可评审稿，回传主控请求该具体设计决定；已有明确确认则继续生产，不反复询问。
设定确认后，按游戏状态生产角色、背景和 UI 等必要资源。每项给出资源 ID、用途、尺寸、透明背景/边缘要求、锚点、安全区和文件名；保持角色身份、比例与颜色一致。
如需要灰白、受击、成功、逃跑等状态，先根据实际玩法列状态清单，再生成素材；不要临时拼几个无关形状替代已确认角色。
优先使用当前可用的专业图像工具；若不可用，交付完整提示词和规格并标记待生成。交付实际素材与视觉规范，记录来源/使用条件和需要后续动画处理的部分。
```

## 4. 动画

派发时机：玩法事件、角色设定及必要资源已确定。首句：“现在，你重新开一个对话，向他发送以下内容，开始你的动画设计：”

```text
根据任务书指定的角色状态与游戏事件设计动画，保持已锁定的造型、数学规则和完成条件。
角色表情和肢体动作优先采用序列帧或精灵图；环境光圈、粒子、飘字、淡入淡出等优先使用 CSS/JS。若采用其他方案能明显改善一致性、性能或维护成本，说明理由并遵守已锁定技术约束。
角色动作交付须注明帧数、帧率、每帧尺寸、排列方式、透明边界、统一锚点、循环/单次、起止姿态和文件路径；检查形体跳变和抖动。没有生产能力时只能交付分镜/帧规格，不能冒充序列帧文件。
给出触发事件、开始/结束状态、结束通知、可否重复/打断、连点时处理、重启时取消方式。环境特效须限定作用区域和时长，不遮挡数学信息，不通过特效偷偷改变判定时机。
交付动作预览（工具可用时）、素材、状态转换表及开发接入说明；说明实际预览设备与尚未验证项。
```

## 5. 音乐与音效

派发时机：玩法循环、事件和视觉情绪足以形成音频规格；无需等待所有动画完成，但不能在玩法未验证时大量制作正式音频。首句：“现在，你重新开一个对话，向他发送以下内容，开始你的音乐与音效设计：”

```text
为本项目制作适合小学课堂的原创背景音乐与交互音效。先列 BGM 规格与 SFX 事件清单，再制作资源。
若有参考音乐，只提取抽象特征：速度范围、节拍、主要音色、情绪、疏密、能量曲线、结构与循环体验。未实际获得或听到参考时明确说明，不编造听感分析。
根据这些特征重新创作，不通过简单变速、移调、换乐器或小幅改动来改造受版权保护作品，不照搬可辨认旋律、歌词或独特编配。记录参考来源与本次原创方向，避免承诺未经核实的授权或版权状态。
BGM 说明时长、循环点、接缝与收尾；SFX 按当前实际事件逐项设计，例如点击、正确、错误、完成和重启。错误音不羞辱学生，不惊吓或掩盖教学反馈；音频不可成为唯一的对错提示。
为每个资源给出 ID、用途、文件名、格式、时长、音量关系、触发时机、优先级及重叠/打断策略。给开发者首次用户操作后播放、静音、重启及切换场景的接入约定。
优先使用当前可用的专业音乐/音效工具。没有音频生成工具时输出可直接复制给工具的原创制作提示词及导出规格，回传清楚标记“规格完成，音频待制作”，不提供虚构下载链接。
交付实际音频或准确标记的待制作规格、事件映射、来源/使用条件及试听结论；未试听须说明。
```

## 6. 测试与迭代

派发时机：v0.5 教师试玩、v0.6 学生试玩或明确修复后复测。首句：“现在，你重新开一个对话，向他发送以下内容，开始你的测试与迭代：”

```text
根据当前阶段组织测试，先区分你能实际运行的技术检查和需要 Leo 在真实课堂收集的证据。
教师试玩：覆盖首次打开、开始、正确答案、错误与再尝试、完成与重玩、静音，以及目标设备触屏/鼠标操作。检验数学题目和答案、锁定规则、反馈可理解性，记录复现步骤和影响。
学生试玩：给 Leo 一张简短观察表，使用匿名编号；不要替他编造学生反馈。观察第一次是否知道点哪里、老师不解释能否开始、第几题熟练、误触发生在哪里、错后是否知道原因、是否主动再玩，以及可观察到的数学策略。记录实际教师提示、操作和学生表述，分开事实与推测。
没有学生记录时先交付测试方案与空表，回传标记“待真实学生试玩”；收到记录后再归纳，不能用成人或模型模拟替代课堂证据。
按影响排列问题：数学错误/无法完成等阻塞问题优先，理解障碍和误触其次，装饰性问题后置。每项给出版本、设备、复现/观察、预期与实际、证据、建议修复专项和复测方式。
提出影响 LOCKED 项的建议时说明理由，由主控安排决定后再修复；不要在测试对话自行更改规则。
交付测试记录、已通过与未通过的验收项、问题优先级和具体迭代建议；不把“喜欢”作为学习效果或正式发布的唯一证据。
```
